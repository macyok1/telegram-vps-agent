# Инструкция для нейросети: разверни моего Telegram VPS Agent

Этот файл можно целиком передать Codex, Claude Code, OpenCode или другой нейросети
с доступом к вашему новому серверу. Это инструкция установщику, а не system prompt
модели внутри бота: runtime prompt уже находится в `apps/telegram-bot/bot.py`.

## Задача

Разверни отдельный экземпляр из `https://github.com/macyok1/telegram-vps-agent` на
**моём** VPS, с **моим** новым Telegram-ботом, **моим** Telegram ID и **моими** ключами
LLM. Результат — работающий личный чат, память/vault и выполнение команд сервера.
Сначала прочитай README.md, SETUP.md, SOURCE.md и код установщика.

## Что узнать у меня

Сначала собери только недостающие данные одним коротким запросом:

- целевой VPS и способ SSH-доступа с правом sudo;
- токен отдельного бота от BotFather (или способ закрыто записать его на сервере);
- мой числовой Telegram user ID;
- уже существующий LiteLLM либо провайдер/API base/model ID/API key для нового;
- нужна ли дополнительная функциональность веб-панели. По умолчанию установи
  только комплект из этого репозитория, без публичного сайта.

Секреты запрашивай и сохраняй через доступный закрытый механизм. Не печатай токены,
пароли, полный env или vault в логах, отчёте, Git и командах с видимыми аргументами.
Если я сам заполню закрытый env, проверь готовность без вывода значений.

## Что делать

1. Проверь ОС, Python 3.12+, systemd, sudo, память, диск и существующие сервисы.
   Эта установка рассчитана на новый отдельный VPS. Если пути или пользователь
   уже заняты, изучи существующий экземпляр и остановись перед его заменой.
2. Клонируй репозиторий, выполни существующие unittest и компиляцию. Не обходи
   падающие проверки. Linux-тесты брокера требуют Linux, а не Windows.
3. Проверь конфигурацию установщика и запусти `sudo bash scripts/install.sh`.
   Он не запускает сервисы и не должен менять SSH, DNS, firewall или чужие сайты.
4. Подключи существующий LiteLLM либо установи Docker по официальной инструкции
   и подготовь новый `gateway/compose.yml` в `/opt/ai-gateway` по SETUP.md.
   Не затирай существующий gateway, не меняй его salt key и не удаляй его тома.
5. Все `REPLACE_...` замени собственными данными экземпляра. Генерируй разные
   master/salt/UI/DB секреты. Для чата создай virtual key. Выбери доступный маршрут
   и модель, поддерживающую tools. Проверь реальный ответ модели через gateway.
6. Запиши `/etc/litellm-telegram-bot.env` (root, 0600), оставь allowlists пустыми,
   Supermemory выключенной. Проверь мой user ID; это не ID бота и не username.
   Внутренний URL LiteLLM задавай без `/v1`.
7. Проверь пустой vault, корректность JSON и права. Существующий vault не обнуляй.
   Не копируй secrets/history/account-файлы разработчика.
8. Убедись, что webhook выключен и на токене нет второго polling-процесса.
   При получении ID через `getUpdates` до запуска используй только мои сообщения;
   не печатай переписку и токен в отчёт.
9. Выполни `sudo python3 scripts/check-config.py`, затем включи и запусти
   `admin-console` и `litellm-telegram-bot`. Проверь их фактическое состояние.
10. Вместе со мной проверь личный `/start`, `/status`, ответ модели, безвредные
    `whoami`/`date -Is` и запись/чтение/удаление тестового ключа `demo`.
    Результат shell подтверждай выводом инструмента, а не обещанием модели.

## Архитектурные условия

- Бот и broker выполняют команды как root. Telegram-команды модели не требуют
  отдельного подтверждения на каждую команду: это сохранённое поведение проекта.
- `/allow` даёт широкий доступ к агенту и его vault. Не разрешай других пользователей
  или группы автоматически, не выдавай это за безопасный режим общего чата.
- Vault и дополнительная документация владельца напрямую отправляются LLM.
  Сообщи мне это свойство до помещения реальных секретов в хранилище.
- Root shell нельзя считать изолированным только из-за ограниченного PATH или
  `NoNewPrivileges`. Это приложение для доверенного личного владельца.
- Shared-модули и брокер обязательны. `bot.py` в одиночку не является комплектом.
  Сокеты `/run/admin-console/control.sock` и `/run/admin-bot-chat/bridge.sock`
  не публикуй через TCP или reverse proxy без отдельного проекта авторизации.
- Статическое меню исходного провайдера не означает, что эти модели доступны у меня.
  Проверяй `/v1/models`; для первого запуска используй `/use bot-model`.
- Локальная память включена. Supermemory optional и по умолчанию выключена;
  для первоначального развёртывания не регистрируй дополнительные сервисы.

## Отчёт

Дай короткий итог: что установлено и где, модель/маршрут, состояния двух сервисов,
какие тесты действительно прошли, команды просмотра логов и перезапуска.
Различай успешные unit-тесты, работающие сервисы и проверенный реальный диалог.
Если последнее проверить не удалось — укажи, что именно мне осталось проверить.
Не сообщай «бот работает», если были только созданы файлы.
