# Telegram VPS Agent

Персональный Telegram-бот для общения с LLM через LiteLLM, выполнения команд на
собственном Linux-сервере, хранения доступов и локальных заметок. Исходники собраны
из рабочего проекта с модулями, необходимыми для отдельного развёртывания.

**Для установки с помощью нейросети:** передайте ей [AI_SETUP.md](AI_SETUP.md) и
этот репозиторий. Пошаговая ручная установка: [SETUP.md](SETUP.md).

## Что внутри

- Общение на русском, переключение моделей и резервные маршруты LiteLLM.
- Root-команды через отдельный Unix-socket брокер с ограничением времени и вывода.
- Локальный JSON vault, чтение его содержимого моделью по смыслу.
- Сохранение ключей и заметок обычным текстом; кнопки сохранения/отмены и
  автоматическое сохранение новых предложений через 10 минут.
- Контроль доступа по Telegram ID; первоначально доступ имеет только владелец.
- Внутренний bridge и SQLite-хранилище сессий для будущего подключения веб-чата.
- Установщик двух systemd-сервисов, шаблон LiteLLM + PostgreSQL и существующие тесты.

## Важно о поведении

Это персональный агент администратора. Разрешённые пользователи и участники
разрешённых групп могут получать доступ к функциям агента, vault и командам:
`/allow` не создаёт отдельную роль «обычный собеседник».
До понимания этого механизма используйте только личный чат владельца.

Команды Telegram-агента выполняются как **root без подтверждения каждой команды**.
Vault и `/root/credentials-and-instructions.md`, если он существует, передаются
выбранному LLM-провайдеру перед запросом; запрос владельца может вернуть пароль
полностью в Telegram. Локальный vault — файл с правами 0600, без шифрования на диске.
Эти свойства сохранены из исходного проекта, это не изолированный публичный сервис.

В пакет не включены реальные токены, SSH-ключи, базы данных, история сообщений,
vault, конфигурации владельца, сайты или скрипты миграции его инфраструктуры.
Друг создаёт собственного бота, указывает свой Telegram ID и использует свои API-ключи.

## Компоненты

| Каталог | Назначение |
| --- | --- |
| `apps/telegram-bot/` | Бот, локальная память, инструменты, тесты |
| `apps/*.py` | Bridge, брокер консоли, задания, хранилище веб-сессий |
| `apps/tests/` | Существующие проверки консоли и хранилища |
| `config/` | Systemd-сервисы и пример конфигурации бота |
| `gateway/` | Необязательный отдельный LiteLLM + PostgreSQL |
| `scripts/` | Подготовка установки, проверка конфигурации и состава публикации |

Основной запуск устанавливает Telegram-бота и брокер. Веб-админка, её HTTP-сервер,
TLS, консоль в браузере, управление аккаунтами и сайты из исходной инфраструктуры
в этот комплект не входят. Внутренний bridge остаётся Unix-сокетом и наружу не открывается.
Домен для Telegram-бота не нужен.

## Команды Telegram

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Справка |
| `/status` | Ресурсы VPS и доступность LiteLLM |
| `/models` | Модели, реально доступные в вашем gateway |
| `/use bot-model` | Переключение на доступный маршрут |
| `/test bot-model` | Тест модели |
| `/vault list` | Имена записей, значения маскируются |
| `/vault show имя` | Полное значение записи |
| `/vault set имя значение` | Предложение записи |
| `/vault del имя` | Удаление записи |
| `/allow`, `/deny` | Изменение доверенных пользователей/групп |

`/menu`, `/accounts` и `/priority` сохранили каталог и сценарий исходного проекта
(DashScope и три аккаунта OpenCode Go). Эти аккаунты и модели не создаются установкой.
Для своего провайдера начните с `/models` и `/use`; статический каталог
`PROVIDERS` можно адаптировать отдельно.

## Разработка и проверки

Python 3.12+, Linux; сторонние Python-пакеты для этого комплекта не нужны.

```bash
export PYTHONPATH="$PWD/apps:$PWD/apps/telegram-bot"
python3 -m compileall -q apps scripts
python3 -m unittest discover -s apps/telegram-bot -p 'test_*.py' -v
python3 -m unittest discover -s apps/tests -p 'test_*.py' -v
bash -n scripts/install.sh
python3 scripts/check-publication.py
```

Linux-проверки консоли используют временные файлы и безвредные процессы; реальные
токены или работающий Telegram-бот для unittest не нужны. На Windows часть проверок
Unix-процессов недоступна: полный комплект выполняется в GitHub Actions на Ubuntu.
Сводка фактически выполненных проверок: [VALIDATION.md](VALIDATION.md).

Происхождение и изменения комплекта: [SOURCE.md](SOURCE.md).
